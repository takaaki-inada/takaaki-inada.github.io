- [Qwen3.8 - How to Run Locally  Unsloth Documentation](https://unsloth.ai/docs/models/qwen3.8)  


この記事では、新たな視覚・推論対応モデルである「Qwen3.8」シリーズをローカル環境で実行するための実践的なガイドと、Unslothが提供する量子化モデル（GGUF、NVFP4等）についての詳細が解説されています。新人エンジニアがローカルLLMやエージェント開発を始める際の重要な情報が網羅されています。

Qwen3.8の主軸となる「Qwen3.8-27B」は、27Bのパラメータを持つ高密度モデルであり、視覚機能と推論機能、最大256Kのコンテキストウィンドウを備えています。17GB程度のRAM/VRAM環境（RTX 5080/4090や24GB RAM搭載のMacなど）でローカル実行が可能であり、エージェントコーディングやチャットタスクに優れた性能を発揮します。更新された「Unsloth Dynamic V3.1」アルゴリズムにより、従来の量子化と比較して同等のサイズで5〜10%の精度向上が実現されています。

また、さらに大規模なモデルとして、2.4Tパラメータ（アクティブ95B）を持つ「Qwen3.8-2.4T-A95B」も紹介されています。フル精度では4.9TBのストレージが必要ですが、1bitのUnsloth Dynamic GGUF（IQ1_XXXSなど）を活用することで397GB（約91%削減）へと大幅に軽量化され、約450GB以上のRAM環境で動作させることが可能です。

利用方法としては、UIアプリケーションである「Unsloth Desktop」を用いた直感的なモデルの検索・ダウンロード・実行のほか、コマンドラインから「llama.cpp」ビルドして実行する方法が提示されています。また、NVIDIAのBlackwell世代GPU（RTX 50X、B200等）を対象とした「NVFP4」量子化モデルの活用により、vLLMやSGLangを介して約1.5倍高速な推論を実現する手順も示されています。モデルの実行時には、思考モード（Thinking Mode）と通常モード（Instruct Mode）で推奨されるtemperatureやtop_pなどのパラメータ設定が異なる点にも注意が必要です。

- [個人開発で5週間150万DL、AIと爆速で作るCAD「SolidCraft」 - FabScene（ファブシーン）](https://fabscene.com/new/interview/solidcraft-open-source-cad-ai-1-5m-downloads-brennen-herbruck/)  


この記事では、米国の開発者Brennen Herbruck氏がClaude CodeなどのAIコーディングツールを活用し、短期間でオープンソースの3D CADソフトウェア「SolidCraft」を開発・公開した事例について解説しています。SolidCraftは、Autodeskの「Fusion」に近い操作の流れを持つパラメトリックな3D CADであり、Windows、macOS、Linux、FreeBSD向けにビルド済みファイルが提供されているほか、ブラウザー上でも動作するのが特徴です。

開発の背景として、Herbruck氏はオープンソースで複数プラットフォームに対応し、モダンなインターフェースを持つCADを求めていました。AI開発ツールの支援を受けたことで、従来は個人では手が届かないと考えていた大規模なソフトウェア開発に着手できたとしています。2025年10月の最初のコミットから約5週間で58回の正式版リリースを行い、GitHubでのダウンロード数は約150万回、スターは1万6000に達するなど、爆発的なスピードで開発が進められました。

技術的なポイントとして、公開当初はRust製のオープンソースカーネル「Truck」を採用していましたが、フィレットやブーリアン演算の処理速度に限界を感じたため、公開から約1カ月後のv0.40.0でNVIDIAのC++形状処理ライブラリ「SMLib」をRustに移植した「SolidCore」へとカーネルを載せ替えています。これにより、スタック全体をRustで統一したまま堅牢な土台を構築することに成功しました。

また、SolidCraftはAIエージェントがCADを直接操作できるMCP（Model Context Protocol）サーバーを内蔵しており、アプリ内からClaude CodeやCodex、Gemini CLIなどのAIエージェントと対話する画面が用意されています。これにより、「人が作った形をAIが引き継ぎ、AIが作った形を人が直す」という人間とAIのシームレスな協働作業を実現しています。開発においては、自動コードレビューサービスの「CodeRabbit」やCI高速化の「Blacksmith」を活用し、1日に約200件ものプルリクエストを処理する体制を整えています。新人のエンジニアにとって、AIコーディングツールやMCPなどの最新プロトコルを実開発に深く組み込み、大規模なOSSを短期間で成長させるプロセスは非常に参考になる事例と言えます。

- [Claude Codeに同じ調査を繰り返させないためのメモの残し方](https://qiita.com/kentasatomi/items/06ccfbf7f6a2a24883ff)  


本記事では、Anthropicが公開したAIエージェントのメモリ管理に関する技術解説「The components of agent memory」の考え方をベースに、開発支援ツール「Claude Code」などのAIエージェントに過去の調査結果やコンテキストを効果的に引き継がせるためのメモの残し方を解説しています。

新人エンジニアがAIを活用して開発を進める際、単に「エラーが解決した」「この設定が必要だった」という結果ベースのメモだけを残すと、将来的に環境が変わった際や別の原因で同じエラーが発生したときにAIが誤った推測に基づいて無駄な調査を繰り返す原因になります。これを防ぐためには、メモの内容を「確認できた事実（根拠となるコードや検証条件）」と「まだ確認していない仮説」に明確に分けて記録することが重要です。

また、「現在のブランチ名」や「テストが全て成功した」といった一時的な状態を永続的なメモに混ぜると、古い情報を現在の正しい情報として誤認させるリスクがあります。そのため、メモには「なぜその判断に至ったのか」「どのような条件や手順で調べたのか」「どのような条件下で見直すべきか」という判断理由や条件を中心に残すべきです。パスワードや接続URLなどの機密情報の実値を含めず、確認すべき設定名やコードの場所を指定することも意識する必要があります。

Claude Codeにおけるメモリ管理としては、人間が継続的な指示やチームの共通方針を書く「CLAUDE.md」と、AIが自動的に好みを記録する「auto memory」の仕組みが存在します。調査終了時にClaudeへ要約やメモリ整理を依頼する際は、単に保存するのではなく「保存せずまず候補を見せること」「確認できた事実と仮説を区別すること」「次回変わり得る状態をルールにしないこと」などを指定するプロンプトを活用し、出力された候補を目視で確認してから適切な場所へ保存することが推奨されます。最後に、新しいセッションで実際にそのメモが正しく参照され、適切な調査手順が提案されるかを検証することで、実用的なメモの品質を維持することができます。
